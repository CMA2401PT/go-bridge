# 生成器实施计划

状态：M0、M1 完成，M2 待实现。每完成一个可验证的阶段单独提交，下面的状态随代码更新。

## 目标与范围

输入一个 Go 包（目录或 import path），分析整个包的导出 API，生成 Go C ABI
适配层、pybind11 C++ 绑定、Python package 和 `.pyi`。生成代码不要求逐字匹配
`examples/expected/`，但复制、共享、类型检查和生命周期行为必须有测试依据。

首版目标是 examples 01–09：

- bool、整数、浮点数、string；多返回值。
- slice（含 bytes、嵌套 slice）、命名标量与命名 slice。
- 命名 struct、导出字段、嵌入与提升成员、值/指针接收者。
- 普通指针、多级指针、命名指针、递归类型。
- 带类型 nil，以及可恢复 panic → Python GoPanic。

暂不支持 any/interface（含 error）、map、channel、数组、函数值/callback、泛型
和可变参数。包级变量、常量的导出另行设计，不沿用旧 gen 的变量导出接口。
命名 bool 的 Python 表示尚未定义（bool 不能被继承），暂时明确拒绝。
基础 bool 正常支持。complex、unsafe.Pointer 不在首版范围。

不支持的类型若只用于包内部，不影响生成；若出现在导出 API 或其依赖中，报告
具体声明/字段/参数路径并停止，不静默遗漏接口。匿名 struct 也按此规则拒绝。
这比历史 examples 中“跳过并警告”的设想更严格，以避免交付不完整的包。

首版构建验证针对本机 macOS/Linux、启用 GIL 的 CPython。Windows、跨平台交叉编译、
free-threaded Python、子解释器、跨生成包的对象互操作不在当前验证范围。

## 已确定的语义

- 包装类位于生成的 C++，由 pybind11 注册；Python `__init__.py` 主要重新导出。
- struct 包装表示 Go 变量，字段中的 struct 读取为视图；参数与赋值复制值。
- slice 包装表示不可变的 slice 头，底层数组共享；不会隐式转换成 Python list。
- `addr()` 对 struct 原变量取地址；`ptr()`/指针构造复制输入值到新变量。
- 不同 Go named/指针类型保持独立，转换显式进行。
- nil 统一采用 09：指针的同类包装，句柄 0，不用 None；nil 接收者交给 Go 执行。
- 每个独立的非 nil Ref 拥有一个持有关系；Go 对象之间保存 Go 引用，不保存句柄。
- 生成器中的 Go 类型模型、Python 接口模型、ABI 描述是不同层；生成文件不是中间表示。
- 生成的包依赖原始 Go 包源码及其构建环境；首版不承诺源码或构建目录可搬迁。

历史样例不是统一版本的快照：06–08 的 nil/panic 行为已经被 09 替代。验收依据
是此处记录的统一规则及相应行为测试，而非复制全部历史测试断言。

## 阶段与验收

### M0：计划与边界

- [x] 记录完整路线、模块职责、支持范围和提交策略。
- [x] 更新仓库首页，区分历史样例、目标能力与生成器实际能力。

### M1：加载包与 Go 类型/API 模型

- [x] 使用 go/packages 加载恰好一个包；尊重多文件、依赖和构建条件。
- [x] 从导出类型/函数开始，通过 go/types 计算类型闭包。
- [x] 保留 named 身份、底层类型、方法接收者、参数、结果与导出字段。
- [x] 归一化 alias，按 Go 类型身份去重，处理递归类型与同名不同包的类型。
- [x] 固定包含受支持的基础类型；struct 的桥接依赖留给 Python 接口规划。
- [x] 不支持的声明提供上下文诊断；不产出半完整模型。
- [x] 测试覆盖 01–09、跨文件、递归、方法签名依赖与拒绝路径。

Go 模型描述 Go 事实，不包含 Python/C ABI 名称。为 struct 补指针等桥接依赖在
后续接口规划阶段完成，不能把每个类型的指针无限加入闭包。

验证：`go test ./internal/gomodel`、`go vet ./internal/gomodel` 通过。M1 只有前端
模型，不代表已经可以为这些类型生成可运行绑定。

### M2：基础值端到端

- [ ] 建立 Python 接口模型，集中处理 snake_case、参数名、保留名与冲突诊断。

- [ ] 生成 `.pyi`、`__init__.py`、`py.typed`、构建入口及 CLI。
- [ ] 从 examples 01–03 实际生成、编译、导入并验证；另测数值边界、字符串错误、

- [ ] 尚未实现的后端类型明确拒绝，不因前端已能分析而宣称支持。

## 工作与提交约定

每阶段可以拆成更小的、可验证提交；先检查 git 状态，不覆盖用户修改。生成产物和
构建目录不提交。提交前运行该阶段适用的测试，记录结果；后端暂不支持的功能通过
显式诊断阻止使用，不保留悄悄降级的兼容路径。

实现中发现规则有问题，可以直接更新本文和相关文档，并在进度报告/提交中说明。
重大未定语义（如命名 bool）不会仅为让代码通过而擅自映射。
